## Context

既有活動以記憶體保存，Socket.IO 推送依角色分流。工作表掃描、順位、計分及回填共用現有活動模型。

## Goals / Non-Goals

支援同一伺服器上的多個瀏覽器工作階段、學號持久化、活動組別與單題控制。正式服務維持 localhost。

## Decisions

- 學號與活動快照由本機私有 JSON 保存，Session 保留在程序記憶體。活動重設清空當輪試題、組別、答案與公布狀態，保留帳號。
- HTTP 與 Socket.IO 均解析同一 HttpOnly Cookie。登入與登出撤銷舊連線，學生只接收本人提交資料。
- 延用全題和逐題流程，新增獨立開關模式，以每題截止時間和明確結算控制公布。
- 教師在學生尚無本輪作答前可調組，避免既有組別限制被繞過。

## Risks / Trade-offs

學號可能遭冒用。重啟保留帳號及活動，使用者需重新登入。實體裝置無法直接連入只監聽 loopback 的服務。
## 共同功能表設計修訂

將活動快照、組別、收件流水號與待判定答覆原子寫入私有 JSON。收件先以單調時鐘蓋戳並持久化，再回覆和排程背景處理。關題先阻擋新收件，再處理既有佇列，最後確定勝者與更新組別分數。判定時間以可跨重啟排序的時間軸計算，原始奈秒用字串保存。教師答覆狀態每 300 毫秒彙整，學生只收到自身狀態和已公布的勝者。CSV 每筆一列。Sheets 批次回填獨立處理，暫時錯誤退避重試。

## 第二輪設計

收件記錄附上活動識別碼，以活動、學號及題號核對重送。老師與學生快照都依登入身分產生。計分以關閉且已清空收件佇列的第一名逐題重新推導。
