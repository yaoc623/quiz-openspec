# 課堂搶答系統

以 Node.js、Express、Socket.IO 和 Google Sheets API 建立的本機課堂搶答系統。活動狀態存於單一服務程序記憶體；重啟服務會清除活動與作答紀錄。

## 安裝

需要 Node.js 18 或更新版本。在專案根目錄執行：

```sh
npm install
```

## 設定 Google 服務帳號

1. 在 Google Cloud 專案啟用 Google Sheets API，建立服務帳號並下載 JSON 金鑰。
2. 將下載的檔案放到專案根目錄，檔名為 `credentials.json`。此檔已列入 `.gitignore`，不要提交或貼到程式碼中。
3. 啟動網站後，老師畫面會顯示服務帳號 email；也可從憑證 JSON 的 `client_email` 欄位取得。
4. 在 Google 試算表右上角按「共用」，將試算表共用給該 email，權限設為「編輯者」。
5. 在老師畫面貼上試算表網址並按「掃描匯入」。系統會掃描所有工作表，尋找同列包含「題號」、「題目」、「作答」的表頭。資料位置依掃描結果與合併儲存格計算。

若尚未放入憑證，網站仍可啟動；匯入或回寫時會顯示繁體中文錯誤。單元測試使用假資料和 mock API，不需要真實憑證或 Google 連線。

## 啟動

```sh
npm start
```

開啟 [http://localhost:3000](http://localhost:3000)。服務只監聽本機 `127.0.0.1:3000`。

## 用三個瀏覽器分頁模擬活動

1. 開啟第一個分頁至 `http://localhost:3000`，身分選「老師」，按「進入活動」。設定組數（預設四組），匯入已共用給服務帳號的 Google 試算表，確認題目摘要後按「開始搶答」。
2. 開啟第二個分頁至相同網址，身分選「學生組別」，選「第 1 組」，按「進入活動」。在題目輸入答案並提交。
3. 開啟第三個分頁，選「第 2 組」進入並提交。老師分頁會即時看到組別、答案、伺服器時間及順位；學生在搶答中只會看到自己組答案。
4. 老師按「結束搶答」，所有分頁會顯示結果；需要寫回時按「回寫成功答案」。

請不要讓同一組在多個分頁同時操作同一題，因為每組每題只接受第一次提交。

## 測試

```sh
npm test
```

測試涵蓋表頭與資料位移、單題和題組解析、合併儲存格、Google Sheets mock 讀寫、憑證錯誤、階段轉換、順位及學生答案隔離。
