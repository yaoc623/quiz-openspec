# Design

## Context

參見 proposal.md 的 Why。此分支原先未包含核心程式和已同步的 `quiz-session` 規格；實作時已帶入本機已完成核心分支的程式與主規格作為基礎。系統使用單一 Node.js 程序、記憶體活動狀態及 Socket.IO；流程階段為「準備中／搶答中／已結束」，匯入狀態由是否有目前題目資料表示。

## Goals / Non-Goals

**Goals:**

- 以一個老師端重設命令清除本輪易變活動資料，並同步讓既有及新連線的畫面顯示未匯入。
- 保留服務狀態中的組數設定，讓新一輪可直接重新匯入題目。
- 使重設可在結束後、試算表回寫前或回寫後執行。

**Non-Goals:**

- 清除、還原或改寫 Google 試算表中的資料。
- 跨服務程序重啟保存活動或組數。
- 允許準備中或搶答中直接重設；本功能只在已結束狀態啟用。

## Decisions

### 伺服器負責驗證並執行重設

新增 Socket.IO 老師控制事件，由伺服器確認發送者角色為老師、目前階段為已結束後才執行重設。瀏覽器確認提示只負責避免誤觸，伺服器仍須驗證角色與階段，避免用戶端繞過介面限制。對其他階段或非老師的命令回覆繁體中文錯誤，且不變更狀態。

替代方案：只在前端隱藏按鈕無法阻擋直接送出事件的連線；以 HTTP 全頁重新載入則無法自然同步其他分頁。

### 將活動重設為「準備中且未匯入」

重設時清空目前試算表識別與解析題目、每組提交、順位/結果及回寫狀態，並把階段設為準備中；保留組數。伺服器產生不含題目或答案的「未匯入」狀態快照，供廣播及新連線初始狀態使用。這符合既有三階段模型，無需增加第四個流程階段；前端以題目是否匯入呈現「未匯入」。

替代方案：新增「未匯入」流程階段會改變現有三階段狀態機，並使開始/結束流程多出不必要轉換。

### 清除範圍僅限本機記憶體

重設不呼叫 Google Sheets API。上一輪若已回寫，其雲端儲存格仍保留；若尚未回寫，本機作答及結果會依重設規則清除。老師匯入相同試算表時，沿用既有匯入流程重新掃描表格並建立新一輪狀態，不以舊記憶體題目或結果作為依據。

替代方案：嘗試清空試算表會破壞原始資料，而且與「新活動」僅重設目前活動狀態的需求不符。

### 前端確認後送出命令，使用狀態快照更新介面

老師端只有在活動已結束時顯示「開始新活動」。點擊先顯示繁體中文確認提示；取消時不送事件。確認後送出伺服器命令，伺服器廣播新的狀態快照；老師和學生頁面共用既有狀態更新流程，清除舊題目、輸入欄位、作答列表及結果區，不依賴重新整理。新連線也從伺服器取得相同快照。

替代方案：分別傳送清除題目、清除答案等多個事件容易令各分頁短暫或永久處於不一致狀態；單一權威快照可讓重設原子化呈現。

## Risks / Trade-offs

- [老師確認後尚未匯入新題目時，畫面只呈現準備中] → 以「未匯入」狀態及清楚提示區分可開始與不可開始的準備狀態。
- [已回寫的同一試算表仍包含上一輪答案] → 重設不宣稱刪除雲端資料；重新匯入時依既有題目解析規則處理，之後的新回寫依當輪答案覆寫其動態目標格。
- [多分頁在命令送達前後短暫顯示不同狀態] → 由單一伺服器快照驅動畫面，且新連線從伺服器取得最新狀態。

## Migration Plan

1. 在活動服務加入已結束階段的重設命令與純記憶體清除邏輯，保留組數。
2. 在 Socket.IO 加入老師授權、階段檢查及全體狀態廣播，並讓新連線取得新狀態。
3. 加入老師端確認操作與教師/學生畫面清空更新，並測試取消、重設、重新匯入與跨分頁同步。
4. 若回退，只需移除新控制和同步處理；重設不會改寫雲端試算表，無外部資料遷移。
