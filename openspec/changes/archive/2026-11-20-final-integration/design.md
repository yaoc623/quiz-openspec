# 期末整合設計

## Context

活動由單一本機程序持有。五個加分提交依序相依，各自已有程式、測試與正式規格。

## Goals / Non-Goals

沿用同一個狀態模型與 Sheets API，維持目前免登入的本機角色流程。

## Decisions

- 在學生頁面依題號與小題索引保存輸入事件，套用同輪狀態時還原。伺服器已提交的值優先。活動識別值防止重連後誤用上一輪草稿。
- 回填入口持有單一操作旗標，從驗證階段到 Sheets 呼叫完成都防止重設、重複回填或變更成功答案。用 finally 解除旗標，以便失敗後重試。
- 保留加分提交的 commit SHA 與封存紀錄。完成核心修復後合併最末端分支，檢查公平排序、駁回、排名、匯出及揭曉的實際資料。

## Risks / Trade-offs

- 外部寫入需要服務帳號及編輯權限。自動化驗證使用模擬 Sheets API，真實寫入另以測試用學習單驗收。

## Migration Plan

依鎖定檔安裝依賴，使用原本的啟動入口。整合只在期末整合分支進行。
