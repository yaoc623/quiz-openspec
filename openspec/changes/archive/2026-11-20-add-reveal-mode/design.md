# Design

## Context

活動結果已由伺服器保存並依角色序列化。沿用現有記憶體狀態與 Socket.IO 同步，不新增資料庫。OpenSpec delta 定義揭曉呈現及學生資料可見性。

## Goals / Non-Goals

**Goals:** 伺服器保存目前揭曉索引；老師可控制全螢幕投影頁；學生只收到已揭曉題目的結果；新連線依目前進度還原。

**Non-Goals:** 不改答案、排名、分數或 Google Sheets 回寫；不保留服務程序重啟前的揭曉狀態。

## Decisions

- 以題目順序的整數索引表示進度，`-1` 代表尚未揭曉。老師透過受權限保護的 HTTP 操作或 Socket 控制前進、返回；伺服器夾限於有效範圍並廣播狀態。相較客戶端自行計數，伺服器狀態可確保重連與多分頁一致。
- 投影頁獨立呈現，使用原有已結束結果和排行榜；進度事件只攜帶已揭曉結果。相較一次把全份答案傳到學生端，可避免開發者工具或隱藏 DOM 提前讀取答案。
- 導覽按鈕及左右方向鍵採相同控制函式，僅老師角色可操作。學生頁只讀取伺服器進度。
- 最後一題揭曉後顯示排行榜，前三名動畫使用 CSS；不依賴外部動畫套件。
- 合理預設：僅「已結束」可進入；重新整理時伺服器保留索引；開始新活動時歸零；無成功答案題目仍依序顯示題號和無人答對；同分沿用現有排行榜順序。

## Risks / Trade-offs

- [伺服器重啟會失去揭曉索引] → 與現有記憶體生命週期一致，重啟後重新匯入並結束活動。
- [鍵盤事件可能誤觸其他控制] → 僅全螢幕投影頁且非輸入元素焦點時處理方向鍵。

## Migration Plan

不需資料遷移；更新程式並重新啟動服務。回退時移除揭曉狀態和頁面，不影響既有活動結果。
