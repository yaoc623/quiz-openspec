# Design

## Context

沿用 `QuizState` 的記憶體活動狀態與角色專用 `publicState`。現有答案以伺服器收件順序決定順位；本 change 需在公平模式開啟時改用判定時間，關閉時維持相容行為。詳細行為以 `specs/quiz-session/spec.md` 為準。

## Goals / Non-Goals

**Goals:** 保存公平模式設定及每筆提交的實際時間、當下成功題數、加權秒數和判定時間；向教師揭露明細，限制學生狀態只帶公平模式開啟旗標；活動結束後公開使用模式與否。

**Non-Goals:** 不變更 Google Sheets 的答案格式，不把延遲時間加到倒數計時，也不在公平模式關閉時改變搶答順位或既有資料隔離。

## Decisions

- 設定放在 `QuizState`：`fairModeEnabled` 預設 `false`、`fairDelaySeconds` 預設 `3`。只允許準備階段修改，延遲必須為正整數。開始活動時設定即固定；`resetActivity` 恢復預設。
- 收到有效答案時，以伺服器目前各題排名第一的答案計算該組成功題數 `k`，整題或題組均只計一題；將 `k`、`k × delay`、實際送出毫秒時間及判定毫秒時間保存於提交記錄。這使後續計算不依賴瀏覽器時鐘。
- 公平模式啟用時，單題的提交依判定時間、實際送出時間、伺服器序號排序，序號確保完全相同時間仍可重現順位；關閉時仍以原收件順位排序。
- 教師快照含提交明細。學生搶答中只取得 `fairModeEnabled`，不包含其他組提交、順位、延遲或判定時間；結束後結果僅公開模式旗標與公開結果，不揭露各組計算明細。
- 老師可在準備中選擇開關與延遲；前端欄位加上伺服器驗證，避免直接 HTTP 請求繞過規則。結果狀態包含本輪公平模式旗標。
- 若後續駁回造成成功題數改變，已存在提交保留其送出當下的 `k` 和判定時間；之後的提交以當下遞補結果計算。這反映需求中的「送出當下」，並避免追溯重寫歷史判定。

## Risks / Trade-offs

- 延遲可能使較晚的實際提交取得較早判定時間；教師明細可解釋結果，學生端不公開他組加權細節。
- 用固定成功題數快照使結果可稽核，但駁回不會追溯改寫舊提交的公平權重；這是保留送出時判定的明確預設。
- 伺服器目前為單一本機程序，重啟後記憶體狀態清除；公平排序沿用此生命週期，不新增持久化層。

## Migration Plan

新欄位採用預設值，未開啟公平模式時所有既有流程維持原順位。更新程式後重啟本機服務即可；回復時移除公平模式設定與計算即可，不需遷移試算表資料。
