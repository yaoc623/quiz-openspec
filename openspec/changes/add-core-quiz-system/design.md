# Design

## Context

參見 proposal.md 的 Why。OpenSpec 目前沒有既有能力規格；本專案是全新的 Node.js 課堂搶答系統。本變更建立 Node.js + Express + Socket.IO + googleapis 的 `npm start` 入口。執行限制為本機 `localhost:3000`、單一服務程序、記憶體狀態與純 HTML/CSS/JavaScript 前端。

## Goals / Non-Goals

**Goals:**

- 以伺服器維護唯一活動狀態、收件時間及各題順位。
- 以 Socket.IO 同步階段，並在伺服器端按角色隔離作答資料。
- 透過 Google Sheets API 動態解析與回寫原表，不使用固定座標或 xlsx 中介檔。
- 讓解析器可用假資料單元測試，不依賴真實 Google 帳號。

**Non-Goals:**

- 帳號、密碼、班級名冊、多租戶或強式身分驗證。
- 資料庫、跨重啟持久化、遠端部署、多程序共享或多個活動並行。
- 將題目文字顯示給學生、自動判分或答案正確性判斷。

## Decisions

### 單一活動狀態由伺服器管理

使用一份記憶體活動狀態保存組數、階段、題目結構與各組答案。HTTP 提供首頁及匯入/設定操作；Socket.IO 傳遞階段、答案提交及結果更新。伺服器驗證階段及組別，每題只有第一筆有效提交取得順位一。用伺服器收件順序與時間，不使用瀏覽器時間。

替代方案：前端計時會受裝置時鐘和網路差異影響；資料庫和多程序同步超出本機記憶體需求。

### 角色資料在伺服器端隔離

連線選擇老師或組別，伺服器依角色分流事件。老師接收所有答案；學生在結束前只接收所屬組別狀態及答案，活動結束後才取得成功組結果。這是本機課堂的無帳密流程，不提供強式身分驗證。

替代方案：把所有答案傳給瀏覽器再以介面隱藏，無法防止學生從網路資料中讀取他組答案。

### Sheets adapter 與純解析器分離

Sheets adapter 讀取 spreadsheet ID、工作表 values、grid metadata 及 merges；純解析器只接收列資料、工作表識別及合併範圍，掃描必要表頭後以零起算索引表示答案格。所有索引都從 API 資料計算，轉換 A1 範圍（若 API 寫入方法需要）也必須在執行時由索引產生，不得使用常數座標。

題號欄合併時以其合併範圍左上角值識別涵蓋列；括號小題標記定位到作答欄右側，單題定位到作答欄或其合併範圍左上角。題目文字僅用於判定資料列是否有題目，解析結果不保存題目文字。Sheets API 直接讀寫雲端資料，不下載或轉換 xlsx。

替代方案：固定欄列或 A1 座標會在表格移動時失效；xlsx 中介檔不符合直接使用 Sheets API 的規則。

### 題組提交完整性

前端依小題數建立一組答案欄位；伺服器要求提交帶有每個小題欄位，並一次記錄整組答案。空字串是有提供欄位時允許的明確答案。

替代方案：小題分開提交會使不同時間的答案合成一組，順位也無法明確定義。

### 原格回寫採批次更新

老師在活動結束後明確操作回寫。系統以解析出的答案目標批次更新成功組答案，不清除或改動其他儲存格；若 API 失敗即回報未完成。重試仍寫入同一動態目標，結果可重複執行。

### 本機憑證

googleapis 讀取專案根目錄 `credentials.json`，從憑證取得服務帳號 email。該檔列在 `.gitignore`，缺失或權限問題以繁體中文回報。測試使用 mock API/假資料，不能要求真實憑證才能通過。

## Risks / Trade-offs

- [程序重啟會清除記憶體狀態] → 明確限定單一程序且介面說明活動不會跨重啟保留。
- [無登入使用者可冒選老師或其他組] → 限定本機課堂使用，伺服器仍依所選角色隔離資料。
- [Google Sheets 權限或表頭格式錯誤] → 顯示繁體中文錯誤；解析失敗不匯入部分題目；用合成資料覆蓋位移及合併儲存格。

## Migration Plan

1. 建立 Node.js `npm start` 入口、相依套件與憑證忽略規則。
2. 建立純解析器及假資料單元測試，再接 Sheets API、活動服務與前端。
3. 以 `npm start` 啟動本機 `localhost:3000` 驗收。失敗時回復本變更新增的 Node.js 檔案/設定。
